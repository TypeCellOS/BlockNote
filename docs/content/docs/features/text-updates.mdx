# Text Updates

With text updates, a client can read a document as markdown, HTML or plain text, change the text, and write it back. An example is an AI agent or a script that edits documents as text, or an HTTP API with a `GET` and a `PUT` for each format.

A write does not replace the document. It applies only the changes of the text. Block IDs, colors, alignment, styles that the format does not show, nesting, and comments on text that did not change stay.

## Installation

```bash
npm install @blocknote/xl-ai
```

The text updates are in the `@blocknote/xl-ai/text-lens` entry point. On a server, the markdown and HTML conversions need a DOM (see [Server-side Processing](/docs/features/server-processing)).

## Read and Write Text

```typescript
import { BlockNoteEditor } from "@blocknote/core";
import {
  getDocumentText,
  markdownFormat,
  updateDocumentFromText,
} from "@blocknote/xl-ai/text-lens";

const editor = BlockNoteEditor.create({ initialContent });

// Read the document as markdown.
const markdown = getDocumentText(editor, markdownFormat);

// A client changes the markdown. Then write it back.
const { operations, warnings } = updateDocumentFromText(editor, {
  format: markdownFormat,
  text: changedMarkdown,
});
```

`updateDocumentFromText` applies the changes in one transaction. `operations` lists the changes by block ID, and `warnings` lists changes that did not apply as written (see [Warnings](#warnings)). To compute the operations without applying them, use `computeTextUpdate` with the same options.

The formats are `markdownFormat`, `htmlFormat` and `plainTextFormat`. HTML shows more data than markdown (for example colors and underline), thus a client can also change that data.

## Which Block Is the Same Block

The text does not contain block IDs. The identity of a block follows the location of its text:

1. Blocks with equal text are the same block.
2. Between these blocks, two blocks are the same if they share most of their words. Thus, a paragraph with many new sentences keeps its ID and props.
3. A block that the text moves keeps its ID, if no other block has the same text.
4. If one block on each side stays between two pairs, the two blocks are the same block. Thus, a paragraph with fully new text at the same position keeps its ID.

A split paragraph keeps its ID on the part with most of its text. Two joined paragraphs keep the ID of the first paragraph.

## Writes From an Older Version

A client can take time to change the text, for example an AI agent. Other users can change the document in that time. Give the document at the version that the client read as `base`. Then the write keeps the changes of the other users:

```typescript
const { text, base } = {
  text: getDocumentText(editor, markdownFormat),
  base: editor.document, // keep this version, for example in your version history
};

// ... later, after other users changed the document:
updateDocumentFromText(editor, {
  format: markdownFormat,
  text: changedText,
  base,
});
```

The client's changes apply to the current document, by block ID. If both sides changed the same field, the client wins. If the client removes a block that another user changed, the block is removed, with a warning. Without `base`, the text applies to the current document, thus a text from an older version changes the newer changes back.

`base` must be the full document (BlockNote JSON) of that version. A version history keeps full documents anyway, because only a full document shows props and nesting.

## BlockNote JSON

`updateDocumentFromJSON` applies a full document as BlockNote JSON in the same way. The JSON contains the block IDs, thus the blocks pair by ID. Only the changed blocks and fields change, and with `base`, the changes of other users stay:

```typescript
import { updateDocumentFromJSON } from "@blocknote/xl-ai/text-lens";

const result = updateDocumentFromJSON(editor, {
  document: changedBlocks,
  base,
});
if (result.error !== undefined) {
  // The JSON does not fit the schema of the editor. The document did not change.
}
```

A block without an ID is a new block. An ID can identify only one block. Thus, a block gets a new ID if an earlier block of the JSON has the same ID, or (with `base`) if another user added a block with that ID after the client read the document.

If the JSON does not fit the schema of the editor (for example an unknown block type or style), the result is `{ error: "invalid-document" }`.

## Y.Doc

For a collaborative document in a Y.Doc, use the `@blocknote/xl-ai/text-lens/yjs` entry point. `base` is the Yjs state of the version that the client read:

```typescript
import * as Y from "yjs";
import { markdownFormat } from "@blocknote/xl-ai/text-lens";
import { getYDocText, updateYDocFromText } from "@blocknote/xl-ai/text-lens/yjs";

const text = getYDocText(editor, ydoc, { format: markdownFormat });
const base = Y.encodeStateAsUpdate(ydoc);

// ... later:
const { update } = updateYDocFromText(editor, ydoc, {
  format: markdownFormat,
  text: changedText,
  base,
});
// Send `update` to the other clients.
```

The `editor` gives the schema and the conversions. To keep comments, give an editor with the comments extension. If the Y.Doc has content that the schema of the editor cannot read (for example a block type of a different schema), the functions throw an error, and the Y.Doc does not change.

The `strategy` option selects how the write merges with the changes of other users:

- `"rebase"` (the default): the changes of the client apply to the current document, by block ID, as for a document without Yjs.
- `"yjs"`: the changes apply to a copy of `base`, and Yjs merges the copy. In the Yjs binding now, a move is a removal and an insert. Thus, if two writers move the same block, or one moves it and the other changes it, the result can have two blocks with the same ID or lose the change.

## Warnings

A result can contain these warnings:

| Warning                     | Meaning                                                                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `multi-part-block-replaced` | The text changed a block that the format shows as more than one block (for example a code block with blank lines, in plain text). The blocks of the text replace the block. |
| `unlinked-block-changed`    | The text changed a part of the text that does not come from one block. The change does not apply.                                          |
| `block-shape-replaced`      | The format shows the block with content of a different shape (for example a table as text), and the text changed it. The block becomes a block of the text. |
| `change-to-removed-block`   | The client changed or moved a block that another user removed. The change does not apply.                                                  |
| `removed-changed-block`     | The client removed a block that another user changed. The block is removed.                                                                 |

## Example Server

The [text lens server example](https://github.com/TypeCellOS/BlockNote/tree/main/examples/02-backend/05-text-lens-server) is an HTTP server with Hono. It gives a document as BlockNote JSON, markdown, HTML and plain text, and accepts a changed document back in each format. It keeps the versions in memory, and uses the `Base-Version` header for writes from an older version. The response of a write gives the document after the write, with the changes of other users, and its version for the next write.

## How It Works

  className="my-4"

  width={900}
  height={395}
/>

1. **Project**: the document goes through the format and back. The result is the view: the document as the format shows it. Each view block links to the document block that gave it.
2. **Parse**: the text of the client gives the blocks of the text.
3. **Align**: the view blocks and the blocks of the text pair by the location of their text (see [Which Block Is the Same Block](#which-block-is-the-same-block)).
4. **Merge and plan**: each pair merges three ways. The base is the view block, "ours" is the block of the text, and "theirs" is the document block. A field that the text changed takes the value of the text. Other fields keep the value of the document, thus data that the format does not show stays. The result is the target document.
5. **Diff**: the target document and the document give the operations, by block ID.
6. **Apply**: the operations become the smallest ProseMirror steps. Unchanged text keeps its identity and its comments, and a collaboration binding sees only the small changes. For an older `base`, the operations first move to the current document.
